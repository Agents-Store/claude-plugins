# LEARNINGS -- project-template-dev

## 2026-09-26 — plugin: renamed from `project-template-creator` to `project-template-dev`

**Problem:** The name carried no process suffix, so it did not say who the plugin is for. It was one of twelve first-generation plugins created before the `{tool}-{process}` convention.
**Fix:** Renamed to `project-template-dev` — template hierarchy management for developers. Directory, `plugin.json` and the marketplace entry changed together; the marketplace `renames` map points `project-template-creator` at `project-template-dev`, so installed copies follow the new name (Claude Code 2.1.193+). Major version bump: command and agent namespaces change from `project-template-creator:` to `project-template-dev:`. Every `/project-template-creator:<cmd>` reference in README, skills and examples now reads `/project-template-dev:<cmd>`.
**Root cause:** Created before the naming convention existed; never revisited.
**Severity:** Minor

## 2026-09-27 — The author's GitHub organization was hard-coded

**Problem:** Every clone, remote and `gh pr create --repo` command named the plugin author's own GitHub organization, and the setup docs pointed `PROJECT_TEMPLATES_DIR` at the author's local folder. For anyone else the commands cloned from the wrong place.
**Fix:** The organization is now `$PROJECT_TEMPLATES_GITHUB_ORG` (documented next to `PROJECT_TEMPLATES_DIR`; if unset, ask the user). Reference docs and examples use the fictional `acme-templates`. Minor bump: a new environment variable.
**Root cause:** Written from inside one team's setup and published as is.
**Severity:** Minor

## 2026-10-03 — README, skills: real install command, current plugin names, stack-{name} rule, current Claude Code conventions

**Problem:** The README installed the plugin with a `claude plugin` subcommand called `add`, which Claude Code does not have (`claude plugin --help` lists `install`). Examples named plugins that no longer exist (the old Vercel, n8n and Trigger.dev names) and the stack naming rule still carried a process suffix. The reference docs taught conventions the Claude Code docs now contradict: `@docs/…` imports as a way to keep CLAUDE.md short (imported files load at launch), `.mcp.json` always gitignored with only a `.example` committed, `AGENTS.md` generated from `CLAUDE.md` by a script, and base workflows kept in `.claude/commands/` with names (`review`, `plan`) that built-in commands shadow. The README listed 5 skills and 4 commands; there are 10 and 8. The audit signatures knew nothing about Payload, grammY, Dokploy, Infisical, restic, Chatwoot, Mattermost, Plane or the pnpm/Bun/uv lockfiles, and the "create a missing plugin" hints pointed at a private plugin.
**Fix:** README installs with `claude plugin marketplace add Agents-Store/claude-plugins` then `claude plugin install project-template-dev@agents-store-claude-plugins` (`/plugin install …` in a session, `--plugin-dir` for a one-off checkout). Examples use `vercel-dev`, `n8n-dev`, `trigger-dev`, and `stack-{name}` for stack plugins (`stack-directus-nextjs`). Templates now: `AGENTS.md` is the single rules file and `CLAUDE.md` starts with `@AGENTS.md` (the script only mirrors into `.cursor/`); `.mcp.json` is committed with `${VAR}` references only and `validate` checks its content with two greps instead of requiring it to be ignored; a committed `.claude/settings.json` carries `enabledPlugins` and `extraKnownMarketplaces`, written by `create`; base workflows are skills, with `plan-feature` and `code-review-project` instead of `plan` and `review`; the 100-line CLAUDE.md limit is labelled as this system's own (the official target is under 200) and `@docs/…` is no longer presented as saving context; stack-specific rules go in `.claude/rules/*.md` with `paths:`. Legacy layouts (old `.mcp.json.example`, generated AGENTS.md, `.claude/commands/`) validate as WARN, not FAIL. `@references/…` pseudo-imports in skill bodies are markdown links. The audit tables gained the missing technologies and lockfiles, and "missing plugin" hints point at `/plugin-dev:create-plugin` from the official `plugin-dev` plugin. The stale `template-creator` keyword is gone from `plugin.json` and the marketplace entry. Version 2.1.0 -> 2.2.0 in `plugin.json` and the marketplace.
**Root cause:** Written against Claude Code of early 2026 and one team's private tooling; never re-checked after the `commands` -> `skills` merge, the `claude plugin` CLI changes, the plugin renames and the 2026-09-06 stack naming decision. Checked against code.claude.com (memory, mcp, skills, plugins/install, plugins/org) and `claude plugin --help` on Claude Code 2.1.288; no live template repository was run.
**Not done here:** the eight command + skill pairs of this plugin are untouched (separate decision). `improve` and `wrap-up` still call `/plugin-creator:feedback` with their documented fallbacks. `/doctor prompt-audit` and `claude plugin eval` (spec "new features" 2 and 5) are not wired in.
**Severity:** Major
