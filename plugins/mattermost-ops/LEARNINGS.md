## 2026-10-03 — setup, troubleshoot, api-reference, common-operations, readme: freshness pass against Mattermost v11.11 / v12.0

**Problem:** `setup`, `troubleshoot` and the PAT table said personal access tokens "never expire until revoked", and the examples minted them with no `expires_at`; since v11.9 a PAT can expire (`401` once it does), an admin can force an expiry (`MaximumPersonalAccessTokenLifetimeDays`), and v11.10 added `POST /users/tokens/rotate` and a non-compliant-token count/revoke. `posts.md` listed the bulk-reactions endpoint under `/posts/ids` (removed in v11.11, backported to 11.9.2 / 11.10.2 / 11.7.11) and `teams.md` listed the Slack team import (removed in v12.0). Both client calls (`/config/client`, `/license/client`) carried an old `format` query parameter the server no longer reads. Nothing warned that v12.0 silently strips sender-identity `props` (`from_webhook`, `override_username`, …) from user/PAT posts or that other users' `last_viewed_at`/`last_update_at` will be omitted instead of `-1`. The README and `troubleshoot` described the official MCP server as "PAT auth; read/search/create posts" and the OpenAPI spec was a pre-v11.10 snapshot quoted as "215 path templates, 600+ operations" (it had 498 / 623).
**Fix:** PAT sections rewritten around `expires_at`, the admin policy, `401` on expiry, rotate and non-compliant count/revoke (`setup`, `auth-sessions.md`, `troubleshoot`); bulk-reactions row removed with a "removed" note; team import marked removed in v12.0 with the mmetl + `mmctl import` path; the `format` parameter dropped; v12.0 warnings in the posting workflow (`common-operations`), `posts.md`, `integrations.md`, `channels.md`, `troubleshoot` and the README; official MCP described as part of the Mattermost Agents plugin (endpoint, auth, tool list, licence limits, doc links); `PUT /channels/{id}/members`, OAuth DCR/PKCE and `/posts/rewrite` rows added. OpenAPI spec re-vendored — 512 path templates / 640 operations (596 core + 44 Playbooks); `scrub-check` result unchanged (0 fail, 2 warn, 3 baselined). **Build recipe (no prebuilt official file exists; the monolithic YAML is a gitignored build artifact):** `git clone --depth 1 --branch <tag> --filter=blob:none --sparse https://github.com/mattermost/mattermost.git && git sparse-checkout set api`; in `api/` run `npm install`; copy `Makefile` to `Makefile.nogo` deleting the `cd server && go run . $(V4_YAML)` line, the "Extracting code samples" echo and the `swagger-cli validate` line; `make -f Makefile.nogo build-v4`; result `api/v4/html/static/mattermost-openapi-v4.yaml` (the `playbooks` target downloads the Playbooks plugin's `master` OpenAPI at build time and merges its tags/definitions/paths; the Go step only adds `x-code-samples`, which the previous vendored file did not have). Use the latest stable tag, not `master` (master is the v12 development line and already lists v12-only changes). Recount with PyYAML: paths = `len(d['paths'])`, operations = GET/POST/PUT/PATCH/DELETE entries, Playbooks = paths containing `/plugins/playbooks`.
**Root cause:** The plugin was written once against an early-2026 snapshot of the API; Mattermost moved PATs to expiring tokens, pruned endpoints and announced v12 behaviour changes since. Not re-checked on a live server from this environment (expiry rejection, the create-with-policy error, rotate, `PUT …/members`) — verify on a v11.9+ sandbox. The upstream build still fails `swagger-cli validate` on three schema nits (bookmarks, custom profile attributes, content flagging); the previous vendored file validated.
**Severity:** Major
