# Learnings

## 2026-10-03 — project-scaffold, auth-flask-login, app-patterns: content moved in from `stack-flask-sqlalchemy-dev` (1.2.0)

**Problem:** The two skeletons `project-scaffold` and `auth-flask-login` (1.1.0) had no content, and the code that was meant to fill them sat in the Flask stack plugin with defects: `db.create_all()` in the factory (so `flask db migrate` answered "No changes in schema detected" and created no revision), a literal `SECRET_KEY` fallback, `db.Column` and `Model.query` throughout, a `GET` logout route, login and register forms without a CSRF token and without `CSRFProtect`, "You haven't registered yet!" for an unknown e-mail (account enumeration), no `next` handling, and a `Model.query.filter_by(user_id=...)` convention that one forgotten filter turned into a data leak.
**Fix:** `project-scaffold` is a complete, buildable project (requirements with the `SQLAlchemy<2.1` pin, `.flaskenv` / `.env` / `.gitignore`, config classes chosen by `APP_ENV`, typed `Base` in `extensions.py`, factory, `User` model, dashboard, `base.html`, `pytest.ini`). `auth-flask-login` has the routes and templates: one login error plus a dummy hash check, scrypt named explicitly, `next` restricted to local paths, registration decided by the unique constraint and the column sizes checked first, logout is `POST` with a CSRF token, password rules by length (NIST SP 800-63B-4: 15 characters when the password is the only factor, no composition rules), Flask-Limiter and `REMEMBER_COOKIE_*` notes, tests. `app-patterns` gained `references/crud-views.md` (CRUD routes, forms with CSRF tokens, dashboard, select box, owner-scoped queries) and a typed `Base` in its `extensions.py`; `jinja2-patterns` logs out with a `POST` form; the `seed` command of `cli-recipes` sets `password_hash`.
**Root cause:** The Flask recipes lived in the stack plugin, written before `flask-dev` existed and never run against Flask 3.1 / Flask-SQLAlchemy 3.1 / SQLAlchemy 2.x. The testing fixture of 1.1.0 yielded the app inside `with app.app_context():`, so every request of a test shared one session, one `g` and one cached Flask-Login user: a missing `commit()` passed (production rolls the row back) and a second client looked signed in as the first user. The fixture now yields outside the context and tests that read the database open their own.
**Severity:** Major (empty migration, shared default secret, GET logout, enumeration, tests blind to a missing commit).
