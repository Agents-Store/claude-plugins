# Learnings

## 2026-10-03 — whole plugin: renamed from `stack-flask-sqlalchemy-dev`, architecture only (2.0.0)

**Problem:** The plugin taught project scaffolding, Flask-Login, the `User` model and CRUD code next to the few rules that really belong to the combination of Flask and SQLAlchemy, and several of those recipes were wrong. `db.create_all()` ran in `create_app()` and the same skill then said to run `flask db init / migrate / upgrade`: the tables already existed, so `flask db migrate` answered "No changes in schema detected" and created no revision, and a production database never got `users` (checked on Flask 3.1.3, Flask-SQLAlchemy 3.1.1, Alembic 1.20.0). `SECRET_KEY` fell back to a literal default, so every deployment that forgot the variable shared one key. `SQLALCHEMY_TRACK_MODIFICATIONS = False` was set although `False` is the default. Every model and query used `db.Column` and `Model.query` (legacy; `Query.get_or_404` emits `LegacyAPIWarning`). Logout was a `GET` route, and the login and register forms had no CSRF token and no `CSRFProtect` was ever initialised. An unknown e-mail got "You haven't registered yet!", which tells a visitor which addresses have accounts. "Filter every query by `current_user.id`" was a convention without a helper, so one forgotten filter exposed another user's rows, and a foreign key from a form (`client_id`) was never checked against the owner. The README said "Python 3.8+" and installed Flask-SQLAlchemy without a pin, which resolves SQLAlchemy 2.1 today (a `MappedAsDataclass` base fails on it, [pallets-eco/flask-sqlalchemy#1420](https://github.com/pallets-eco/flask-sqlalchemy/issues/1420)).
**Fix:** Variant A (decision 2026-09-06): a stack describes the architecture and names its parts in `dependencies` (`flask-dev`, `sqlalchemy-dev`); a skill stays when it links two tools and moves out when it explains one. Moved: `init-project` to `flask-dev:project-scaffold` (complete file set; `APP_ENV` picks the config class; no `create_all()`; `SECRET_KEY` required; `pytest.ini`); the Flask-Login routes, templates and CSRF to `flask-dev:auth-flask-login` (one login error plus a dummy hash check, `next` restricted to local paths, logout is `POST`, registration decided by the unique constraint); the `User` model to `sqlalchemy-dev:model-patterns` (`references/flask-login-user.md`, with `OwnedMixin`); the data-isolation queries to `sqlalchemy-dev:query-patterns` (`references/owner-scoped-queries.md`: `owned_by()`, owner-scoped fetch by id, foreign keys from forms, an isolation test); the CRUD routes, forms and templates of `flask-sqlalchemy-wiring` to `flask-dev:app-patterns` (`references/crud-views.md`, now with CSRF tokens, validation and `Post/Redirect/Get`). Kept and rewritten thin: `full-feature` (a migration check, scoped queries, a second-user test, a statement-count test) and the agent. New: `layers-and-boundaries` (where `db` lives, the app context, the transaction boundary, `expire_on_commit`, N+1 at the route-to-template edge, what the `app` test fixture hides). `README` states Python 3.10+ and the `SQLAlchemy<2.1` pin.
**Root cause:** The plugin was written when no technology plugin existed and was never re-checked against Flask-SQLAlchemy 3.1, SQLAlchemy 2.x or Flask 3. Checked by running: a project built from the skills as written (Flask 3.1.3, Flask-SQLAlchemy 3.1.1, SQLAlchemy 2.0.54, Alembic 1.20.0, Flask-Login 0.6.3, Flask-WTF 1.3.0) creates `users` in the first revision, and the tests pass under `python -W error`. Two boundary claims were measured: a missing `commit()` passes a test that keeps one app context open and loses the row in production (`db.session.remove()` before the assertion catches it), and a list view without `undefer` issues 24 statements for 22 rows against 4 for 2.
**Severity:** Major (empty migration, shared default secret, cross-user data exposure). Breaking: the plugin is renamed `stack-flask-sqlalchemy-dev` to `stack-flask-sqlalchemy` (the marketplace `renames` map moves installed copies; update `enabledPlugins` entries and skill references such as `stack-flask-sqlalchemy-dev:init-project`, which is now `flask-dev:project-scaffold`), and the skills `init-project`, `auth-integration` and `flask-sqlalchemy-wiring` are gone, hence 2.0.0.
