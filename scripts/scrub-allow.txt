# Format:  path:rule-id:reason
#   path     repo-relative path or fnmatch glob
#   rule-id  one rule from scrub_check.py (`*` exempts the file entirely —
#            only ever for third-party payloads we do not author)
#   reason   why this is not a leak. Mandatory; the gate rejects an empty one.
#
# GOVERNANCE: a line here may only be REMOVED in an ordinary pull request.
# ADDING a line requires its own PR that touches nothing else, so the exception
# is reviewed on its own merits instead of riding along with a feature. CI
# enforces this (.github/workflows/scrub.yml, "baseline may only shrink").
#
# Before adding a line, try the fix first: a placeholder (<instance>,
# <data-root>, <compose-root>, <domain>), a documentation address
# (example.com, 203.0.113.10), or moving the value into runtime discovery or
# the operator's own config file.

# --- published product endpoints of plugins in this marketplace -------------
# A plugin for a hosted product ships that product's own public MCP endpoint,
# the same way the vendor plugins do. Judged here rather than allow-listed in
# the gate, so the gate itself carries no deployment-adjacent name.
#
# The root .mcp.json is the aggregated catalogue and therefore the one surface
# where a self-hosted, credential-bearing URL is most likely to be pasted by
# accident. A file-wide permit here would wave that through, so the exception is
# narrowed to ONE value with a `#sha256-<prefix>` selector: the digest of the
# excerpt as the gate prints it. Every other real endpoint on this surface still
# fails, and adding one means computing its digest in its own pull request:
#   python3 scripts/scrub_check.py --no-baseline --format json .mcp.json
#   printf '%s' "<excerpt, lowercased>" | shasum -a 256
.mcp.json:private-host#sha256-ec7bc04324d59234:one product's published MCP endpoint, pinned by value digest so a self-hosted endpoint pasted into this catalogue is still caught
